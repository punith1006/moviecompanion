Feature 2: Smart Recommendation Engine
User Story: "As a user, I need fresh recommendations that match my taste and don't repeat what I've already seen or rejected."
Technical Requirements:

Input: User preferences from MongoDB + current mood/request
Process:

Query TMDB/OMDB API for content matching preferred genres
Filter out already-watched titles from MongoDB
Apply anti-repetition logic (track rejected suggestions)
Rank by relevance score (genre match + rating + recency)


Output: 3-5 recommendations with title, year, genre, rating, brief synopsis

Filtering Logic:
pythondef get_recommendations(user_id, genre=None, mood=None):
    user_data = mongodb.get_user(user_id)
    watched_titles = [show['title'] for show in user_data['watched_shows']]
    rejected_titles = user_data['rejected_suggestions']
    
    api_results = tmdb_search(genre=genre, min_rating=7.0)
    
    filtered = [
        show for show in api_results 
        if show['title'] not in watched_titles 
        and show['title'] not in rejected_titles
    ]
    
    return rank_by_preference(filtered, user_data['preferences'])[:5]
```

**Success Metric:** 0% suggestion overlap with viewing history; >80% user acceptance rate

**Demo Impact:** Show 3 rounds of recommendations without repeats, with real-time filtering.

**Build Effort:** 4 hours (API integration + filtering logic + ranking algorithm)
```

```
### 4.2 Data Flow for Key Use Cases

#### **Use Case 1: Get Recommendations**
```
1. User: "Recommend a sci-fi series"
2. ADK Intent Router → Recommendation Handler
3. Query MongoDB → Get user preferences & watch history
4. Call TMDB API → Search sci-fi series (min_rating=7.0)
5. Filter results → Remove watched/rejected titles
6. Rank by relevance → Apply preference scoring
7. ADK Response Generator → Format top 3 recommendations
8. Return to user with synopsis and metadata
```

#### **Use Case 2: Get Recap**
```
1. User: "What happened in Breaking Bad?"
2. ADK Intent Router → Recap Handler
3. Query MongoDB → Get last watched episode (S5E14)
4. Call TMDB API → Get episode summary
5. ADK LLM → Generate conversational recap
6. Return to user with "Last time on Breaking Bad..."
```

#### **Use Case 3: Interactive Quiz**
```
1. User: "Let's play a quiz"
2. ADK Intent Router → Quiz Handler
3. Query MongoDB → Get random watched show + character quotes
4. ADK Response Generator → Format quiz question
5. User answers → Validate response
6. Track score → Store in session state
7. Offer next question or end quiz

8.2 Anticipated Questions & Answers
Q: How is this different from Netflix's recommendation system?
A: Netflix uses collaborative filtering (what similar users watched). We use explicit memory and user-stated preferences, which means we can explain why we recommend something and avoid showing you the same suggestions repeatedly. Plus, we're platform-agnostic—works for anything you watch.
Q: Can this scale to multiple users?
A: Absolutely. The architecture is designed with user_id as a primary key. For the MVP, we focused on single-user experience to perfect the core features, but multi-user is just a schema extension away.
Q: What if the API doesn't have a show?
A: We have a fallback chain: TMDB → OMDB → Web search scraping. For the demo, we focused on popular content that's well-indexed, but the system gracefully handles missing data.
Q: How do you prevent hallucinations in recaps?
A: We ground the LLM's generation in actual episode summaries from APIs. We're not asking it to "remember" the show—we're asking it to "summarize this text conversationally," which is a much more reliable use case.
Q: Is the quiz data manually entered?
A: For the MVP, we seeded 50+ quotes/facts from popular shows. For production, we'd generate quizzes dynamically using the LLM based on show metadata, or crowdsource from fan wikis.
